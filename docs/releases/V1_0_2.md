# Release v1.0.2 — Atualização Segura e Recuperação do PWA

## Problema observado
Após a v1.0.1, a confirmação do aviso de atualização podia deixar o app em tela vazia com apenas o fundo carregado. A limpeza manual dos dados do site restaurava o funcionamento, mas colocava em risco registros reais.

## Causa técnica mais provável
A auditoria encontrou atualização por `registerType: 'prompt'`, `skipWaiting: false` e botão chamando ativação imediata sem aguardar `controllerchange` nem limitar reload. Em conjunto com rotas `React.lazy`, chunks JS com hash e cache de navegação, uma página HTML antiga podia tentar importar assets removidos ou um novo Service Worker podia assumir no meio da sessão.

## Solução
A v1.0.2 coordena a ativação do Service Worker, aguarda troca de controller, recarrega apenas uma vez com `titan-update-reload-attempted` e adiciona recuperação para falhas de chunk com fallback global.

## Preservação de dados
Nenhum fluxo automático apaga IndexedDB, fotos, treinos, refeições, preferências ou histórico. Apenas caches obsoletos do Workbox são limpos.

## Limitações conhecidas
A validação offline/update completa ainda depende de navegador real instalado como PWA e publicação de duas versões consecutivas.

## Recuperação manual
Se a tela de recuperação aparecer, use **Recarregar aplicativo**. Não limpe dados do navegador sem exportar backup se houver registros reais.
